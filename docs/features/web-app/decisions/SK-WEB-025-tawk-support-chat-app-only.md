# SK-WEB-025 — Tawk.to support chat on the product `/app` surfaces only

- **Decision:** The Tawk.to live-chat widget loads on the `/app` product surfaces only (`SupportChat.astro`, mounted beside `<AppAnalytics />` on `/app`, `/app/new`, `/app/connect`, `/app/keys`), never on marketing/blog/vs/solve. It is the official async embed snippet with one deviation: the injection waits for `DOMContentLoaded` so Tawk cannot read a `#nlq=` handoff fragment off `/app/new/`'s URL before the deferred strip removes it (`SK-ANON-015` owns that rule). The property ID in the `embed.tawk.to` URL is publishable by design — it grants chat access, nothing else. Tawk's three hosts (`embed`/`va`/`cdn.tawk.to`) are denylisted in `lib/boot-fallback.ts#EXTENSION_PREFIXES` (plus the `Base.astro` hand-copy, drift-pinned by `boot-fallback.test.ts`) so a Tawk-side throw never paints the boot-fallback panel or spams `/v1/errors/web`; the widget loading async means its failure leaves the app pages fully functional. **Visitor identity:** the signed-in account's name / email / nlqdb user id are attached via `Tawk_API.setAttributes`, so the operator sees the account instead of Tawk's anonymous visitor id. Tawk Secure Mode requires an `HMAC-SHA256(email, TAWK_TO_API_KEY)` hash to accept name/email — computed server-side by `GET /api/tawk/identity` so the key never reaches the browser. Unprovisioned key ⇒ the endpoint omits the hash and Tawk keeps the anonymous id (no error), so the feature degrades cleanly before the secret is set.
- **Core value:** Free, Effortless UX, Bullet-proof
- **Why:** A signed-in user hitting a wall inside the product is the highest-signal pre-PMF inbound moment (`docs/founder-playbook.md` inbound-triage SLA); an in-page chat removes the "open GitHub, write an issue" detour. Tawk.to is the free, mature option per `GLOBAL-033` (unlimited agents/chats at $0). Scoping to `/app` preserves the marketing Lighthouse-100 + no-cookie-banner posture (`GLOBAL-034`) — Tawk sets its own cookies, so it must never ship on public pages.
- **Consequence in code:** `apps/web/src/components/SupportChat.astro` included by the four `/app` pages; Tawk hosts appended to `EXTENSION_PREFIXES` in `apps/web/src/lib/boot-fallback.ts` and the `Base.astro` inline copy; user-facing disclosure in `apps/web/src/pages/privacy.astro`, channel policy in `SUPPORT.md`, sub-processor row in `SUBPROCESSORS.md`. Visitor identity is wired by `apps/web/src/lib/tawk.ts` (fetches `/api/tawk/identity`, calls `setAttributes`) and the `GET /api/tawk/identity` handler in `apps/api/src/index.ts` (HMACs the session email with `env.TAWK_TO_API_KEY` via `hmacHex`); the key is mirrored by `scripts/mirror-secrets-{gha,workers}.sh` + listed in `.env.example`, and injected into previews by `preview-app.yml`. The name/email transfer to Tawk (US) is disclosed as legitimate-interest processing in `privacy.astro` (Support chat + legal-bases sections) and `SUBPROCESSORS.md` (DPF transfer basis — tawk.to self-certifies to the EU/UK/Swiss–US Data Privacy Framework); keep those in sync if the attribute set changes, and a deletion request must delete the Tawk visitor too. The Tawk cookie's ePrivacy consent is handled by **Tawk's own native Consent Form** — a dashboard toggle (Administration → Chat Widget → Consent Form) that blocks its cookies/localStorage until the visitor accepts in-widget, keeping the bubble visible for everyone (`SK-WEB-029`); the toggle is operator config, not repo code, and MUST stay enabled. PostHog's cookie is gated separately by the first-party `/app` consent prompt (`SK-WEB-029`). Adding a new `/app` page includes `<SupportChat />` next to `<AppAnalytics />`; a marketing page must not.
- **Alternatives rejected:**
  - **Site-wide embed in `Base.astro`.** Ships a cookie-setting third-party script to every marketing page — breaks the `GLOBAL-034` posture and the privacy page's no-tracking-cookies stance.
  - **Intercom / Crisp.** Free tiers cap seats/features that Tawk gives away; fails strict-$0 (`GLOBAL-033`).
  - **No chat (issues/discussions only).** Loses the stuck-in-product inbound moment; a GitHub round-trip filters out exactly the confused-user signal the founder needs.
