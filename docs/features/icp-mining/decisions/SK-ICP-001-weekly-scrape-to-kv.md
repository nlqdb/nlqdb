# SK-ICP-001 — Weekly HN + Reddit scrape writing raw items to KV

- **Decision:** The `icp_pipeline` row in `apps/api/src/scheduled/jobs.ts` (`when: weeklyAt(1, 6)` — Monday 06:00 UTC on the single cron trigger, SK-HDC-023) calls `runIcpScrape`, which queries HN Algolia (10 pain-keyword searches), Reddit (16 subreddit/query pairs), GitHub Issues (5 queries; `GH_TOKEN`-gated; rolling `created:>` 7-day filter), GitHub Discussions (5 queries via GraphQL; same gate + filter), Stack Overflow (5 tag+query pairs via SE API 2.3), Indie Hackers (5 P1-pain queries via `feed.indiehackers.world`), and Dev.to (5 tag queries via Forem API) for posts from the previous 7 days. Each item deduped against a 90-day seen-window; new items written to KV as JSON. **(The per-item key schema is replaced by [SK-ICP-015](./SK-ICP-015-batched-kv-writes.md) — one `icp:seen` index + one `icp:items:<YYYYMMDD>` array per run.)** LogSnag `#icp-mining` reports new vs. skipped per source. Per-source `.catch` isolation: one failing source never kills the others.
- **Core value:** Simple, Bullet-proof
- **Why:** Mining public complaints at scale gives the unfiltered language personas use — current persona docs are hypotheses, not evidence. KV storage is free on the Workers tier. Monday after weekend activity maximises signal. 90-day dedup prevents reprocessing while letting long-tail items cycle out.
- **Consequence in code:** `apps/api/src/icp-scrape.ts` is the single owner; `IcpScrapeDeps.fetch` overridable for tests; OTel spans wrap every external fetch (GLOBAL-014). The job row runs scrape → score → cluster and logs `{ msg: "icp_scrape_completed", newItems, skipped, sources }`; the schedule is the row's predicate, not a cron expression. `LOGSNAG_TOKEN` / `LOGSNAG_PROJECT` optional; skipped silently when absent.
- **Alternatives rejected:** Separate Worker (more infra; existing has capacity); R2 (overkill — KV is sufficient; see Open questions); daily cron (weekly is enough for Phase 1; daily burns KV quota on noise).
