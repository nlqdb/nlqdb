# SK-HDC-015 — Compiler auto-generates defaults for single-column integer/uuid primary keys and record-time columns

- **Decision:** `autoDefault(col, table)` in `apps/api/src/db-create/compile-ddl.ts` is the one place the compiler adds a default the plan did not supply, and `compileTable` (create and widen new-table) is its only caller. A single-column `integer`/`bigint` PK gets `GENERATED BY DEFAULT AS IDENTITY`; a single-column `uuid` PK gets `DEFAULT gen_random_uuid()`. A **record-time column** — name matching `^(created|updated|inserted|added|modified)_(at|on)$` — gets `DEFAULT now()` (`timestamp_tz`) or `DEFAULT CURRENT_DATE` (`date`). Composite PKs, `text` PKs, domain dates (`due_at`, `scheduled_at`, `published_date`) and columns that already carry a plan `default` are untouched. Widen's `ADD COLUMN` never gets one (`SK-SCHEMA-008`).
- **Core value:** Bullet-proof, Seamless auth
- **Why:** The schema-inference prompt (`packages/llm/src/prompts/schema-inference.ts`) does not teach the LLM about `IDENTITY` / `SERIAL` / `gen_random_uuid()`; it almost always emits `id` as `{type: integer, nullable: false, default: null}`. The planner LLM then emits `INSERT INTO t (name, ...) VALUES (...)` without `id`, Postgres rejects the row on the NOT NULL primary key, the exec catch in `apps/api/src/ask/orchestrate.ts:377` maps that to the generic `db_unreachable` envelope, and the chat renders `Couldn't reach the database — try again.` — i.e. the seamless `anon-create → sign-in → write` arc that `SK-ANON-014` is supposed to guarantee dead-ends at the first authed write. Reproduced live on the PR-192 preview Worker (anon `create users table` → mock sign-in → `add row: name='Alice', email='alice@example.com'` → 502 `db_unreachable`, planner-emitted SQL `INSERT INTO ...users (name, email) VALUES (...)`). Putting the default policy in the deterministic compiler per `SK-HDC-002` keeps both LLM calls naive about PK shape (schema-inference doesn't need to know IDENTITY syntax; the planner doesn't need to reason about which columns to include in INSERT lists). `BY DEFAULT` rather than `ALWAYS` so `apps/api/src/db-create/neon-provision.ts`'s sample-row inserts can still pass explicit ids without being rejected. **Record-time columns, measured 2026-10-06 (run 233):** the free chain inferred 9 app schemas, and 12 of their 16 `created_at` columns came back `NOT NULL` with no default (3 carried `now()`, 1 was nullable). Every app INSERT that omits the column failed with 23502. The run-232 preview walk hit the same thing on `restaurants.created_at`. On those 9 schemas, app-shaped INSERTs went from 13/26 to 26/26 against Postgres 16. The column name decides because the clock is the right value only for a record-time column. A domain date the app forgot is a bug the app should see, not a silent `now()`.
- **Consequence in code:** `compileColumn(col, compilerDefault)` takes the string `autoDefault` returns, and the plan's own `default` wins over it. `sample-rows.ts` ([`SK-HDC-019`](./SK-HDC-019-deterministic-sample-row-salvage.md)) calls the same `autoDefault`, so an omitted auto-filled column is never pruned as a 23502. `compile-ddl.test.ts` and `sample-rows.test.ts` pin both rules. Every create surface goes through this compiler, so all of them get the behaviour without surface changes (`GLOBAL-003`).
- **Alternatives rejected:**
  - **Update the schema-inference prompt to emit `default: "gen_random_uuid()"` / `now()`.** LLM non-determinism gives partial coverage: the same chain already wrote `now()` on only 4 of the 25 date/time columns it inferred. The deterministic compiler is `SK-HDC-002`'s seam.
  - **Default every NOT NULL `timestamp_tz` / `date` to the clock.** That would silently write today into `interviews.scheduled_at` or `books.published_date` (both seen in the run-233 sample) when the app omits them.
  - **Update the planner LLM to include all NOT NULL columns in INSERTs.** Pushes complexity into the read/write path and asks the LLM to invent values for arbitrary types (what's a sensible default for `created_at`? `status`?).
  - **`GENERATED ALWAYS AS IDENTITY` instead of `BY DEFAULT`.** Forbids explicit ids in `INSERT`, breaking the provisioner's sample-row inserts (`neon-provision.ts` passes the LLM's `sample_rows[].values.id`).
  - **`SERIAL` / `uuid_generate_v4()`.** Pre-PG10 and extension-required forms; `IDENTITY` + `gen_random_uuid()` are PG13+ built-ins and Neon runs PG16.
