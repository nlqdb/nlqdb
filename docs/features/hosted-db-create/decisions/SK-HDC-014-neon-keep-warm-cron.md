# SK-HDC-014 — Neon Free-tier keep-warm: one `SELECT 1` every 4 min, Mon–Fri 13–21 UTC

- **Decision:** The `neon_keep_warm` row in `apps/api/src/scheduled/jobs.ts` (SK-HDC-023) fires on every 4-minute tick whose scheduled minute satisfies `weekdaysBetween(13, 21)` and issues one `SELECT 1` via `keepNeonWarm(databaseUrl)` — in the WASM-free `pg-client.ts` with the `neon(...)` carve-out per GLOBAL-021, because the cron isolate never runs the create path's WASM shim and must not import through `build-deps.ts`'s libpg-query chain (SK-ASK-024). Outside the window the row is not due and Neon is left to auto-suspend.
- **Core value:** Honest latency, Fast, Free
- **Why:** Trace `66fb421f92648b56f90ed1e5ab0c1e01` (2026-05-13) — `db.transaction` cost 6.8 s on the first anon `db.create` in 6 h, matching Neon's Free-tier 5-min compute auto-suspend cold-start ([Scale to Zero](https://neon.com/docs/introduction/scale-to-zero)). A 4-min interval keeps compute resident inside business hours (EU afternoon + US morning). Budget: 8 h × 22 weekdays × 0.25 CU min ≈ **44 CU-h/month**, 56% under the [100 CU-h Free budget](https://neon.com/docs/introduction/plans). The trigger itself ticks all week (SK-HDC-023); the budget holds because the window guard is in the predicate, and that predicate is unit-tested at the window's edges (12:56 / 13:00 / 21:56 / 22:00, Sat).
- **Consequence in code:** The window lives only in the row's `when`; widening it is a budget change and needs a new figure here. `keepNeonWarm()` (exported from `pg-client.ts`) keeps the `@neondatabase/serverless` import in one file. Errors are logged by the dispatcher (`scheduled_job_failed`) and never re-thrown; success is silent — 360 log lines/day is pure noise. `DATABASE_URL` unset ⇒ `neon_keepwarm_skipped`.
- **Alternatives rejected:** 13-h window (`9-21`, ~71.5 CU-h/mo, only 29% headroom); 6-min interval (re-pays cold start every fire); an unguarded always-on ping (busts budget ~2.6×); Neon Scale plan (kills `GLOBAL-013` no-card promise); logical replication keep-warm (over-engineered).
