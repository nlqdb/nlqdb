# SK-HDC-023 — One `*/4 * * * *` cron trigger; every scheduled job is a row in a declarative job table

- **Decision:** `apps/api/wrangler.toml` declares exactly one cron trigger, `*/4 * * * *`. `scheduled()` delegates to `apps/api/src/scheduled/jobs.ts`, where every scheduled task is one `Job = { name, when: (t: Date) => boolean, run: (env) => Promise<void> }` row in `JOBS`. The dispatcher evaluates `when` against `new Date(controller.scheduledTime)` (the exact scheduled minute, not wall-clock, so no drift) and runs each due job in table order with per-job failure isolation. Schedules are expressed with three UTC predicates — `at(hour, minute)`, `weeklyAt(day, hour)`, `weekdaysBetween(fromHour, toHour)` — never as cron strings in code.
- **Core value:** Free, Simple, Bullet-proof
- **Why:** Cloudflare's Free plan caps cron triggers at **5 per account**, and this account hosts other projects. The api Worker was using 3 (`0 4 * * *`, `*/4 13-21 * * MON-FRI`, `0 6 * * MON`) and had a 7th task queued (memory TTL sweep, SK-PIVOT-011) that would have needed a 4th. Consolidating to one trigger frees 2 slots today and makes the count independent of how many jobs we add. The 4-minute tick is forced by SK-HDC-014 (keep-warm must fire strictly under Neon's 5-min auto-suspend); every other job is a minute-exact predicate on that tick. The `if/else`-on-`controller.cron` chain also carried a string-mirroring hazard (a typo routed a schedule into the wrong branch, hence the unknown-cron guard) — the table removes the strings entirely.
- **Consequence in code:** `wrangler.toml` `[triggers].crons` has one entry; adding a second is a reviewer reject. A new scheduled task is **one row in `JOBS`** — no new trigger, no constant, no dispatch branch, no doc change outside the owning feature's SK. `when` is pure (`getUTC*` only) so selection is unit-tested by feeding a `scheduledTime`. Jobs keep their own env gates (`DATABASE_URL`, `TINYBIRD_TOKEN`, `GH_TOKEN` …) and their own success logs/spans; the dispatcher logs only `scheduled_job_failed { job, message }` so the 360 keep-warm fires/day stay silent on success (SK-HDC-014's noise bar). Day-of-week in predicates is JS `getUTCDay()` (0 = Sun … 6 = Sat) — the Cloudflare `1-7` cron convention no longer appears anywhere.
- **Alternatives rejected:** *Keep 3 triggers* — 60% of the account's cron budget for one Worker, and the 4th job was already blocked. · *Chain of `if (hour === …)` in `scheduled()`* — the 6-instance if/else this replaces; each new job re-derived the gating and isolation by hand. · *A second Worker for low-frequency jobs* — a Worker per schedule spends the same trigger budget. · *Durable Object alarms* — not on the Free plan's default path and heavier than a predicate. · *`setInterval`/wall-clock in-Worker* — Workers have no long-lived process; `scheduledTime` is the only drift-free clock.

## Leverage record (design-for-leverage)

**Category:** "scheduled job on the api Worker".

**Discovery (2026-09-02):** `grep -rn -E 'scheduled\(|crons|scheduledTime|ScheduledEvent' --include='*.ts' --include='*.toml' --include='*.md'` → the only handler is `apps/api/src/index.ts scheduled()` (3 `controller.cron` branches; the 04:00 branch chains 4 tasks). Instances today: **6** — keep-warm (SK-HDC-014), anon sweep (SK-ANON-002/012), GTM snapshot (SK-GTM-003), premium meter reconcile (SK-PREMIUM-017), workload analyser (SK-MIGRATE-001), ICP scrape→score→cluster (SK-ICP-001..003) — plus **1 pending**: agent-memory TTL sweep (`apps/api/src/memory/expire.ts`, SK-PIVOT-011, E-04 step 3). Past the 3+ threshold → build the table (rung 3), not another branch.

**N+1:** the next scheduled job is one `JOBS` row: `{ name, when: at(3), run }`. Zero trigger, config, or dispatcher edits.

**Second consumer (memory TTL sweep):** *not wired* — spend-with-seams. E-04 step 3 lists three remaining pieces besides the cron branch: (b) a D1 enumeration of memory-preset DBs, (c) a new **schema-owner** exec adapter (the DELETE must bypass RLS; reusing `buildHostedExecSteps`' `SET LOCAL ROLE` silently deletes nothing, and `build-deps.ts` cannot be imported on the cron isolate per SK-ASK-024), (d) the `nlqdb.memory.expire` span + counter. (c) is a security-sensitive owner-role path with no existing implementation, and the lazy on-write sweep already keeps memory decaying. The seam is the row; the sweep lands as one row when (b)–(d) exist.

**Verdict:** invest. Diff composition: ~60% generic capacity (`Job` type, 3 predicates, dispatcher, tests), ~40% moving the 6 existing tasks into rows; index.ts loses ~250 lines of branch code. The 7th job costs one row.
