# SK-HDC-022 — An inferred foreign-key column is never NOT NULL unless it is part of the child's primary key

- **Decision:** `inferSchema` ends with `relaxSpeculativeForeignKeys(plan)` (pure, in `apps/api/src/db-create/infer-schema.ts`): for every `foreign_keys` entry, each `from_column` that is **not** a member of the child table's `primary_key` is forced to `nullable: true`. The FK constraint itself, its `on_delete`, and every non-FK column are untouched — referential integrity still rejects a value naming no parent; only the *mandatory* part goes. A plan with no foreign keys is returned unchanged (identity), and hand-authored presets ([`SK-HDC-020`](./SK-HDC-020-agent-memory-preset.md)) bypass `inferSchema` entirely, so their deliberate `NOT NULL` FKs stand.
- **Core value:** Goal-first, Bullet-proof, Engine quality
- **Why:** A goal string names the *thing to store*, never the parent row a future child belongs to, so a speculative `NOT NULL` FK makes the creator's most obvious next action structurally impossible. Measured in production (D1 registry row `db_ideas_db_1ec135`, 2026-08-14): "a database of ideas" inferred `users(Alice, Bob, Carol)` seeded per [`SK-HDC-019`](./SK-HDC-019-deterministic-sample-row-salvage.md) plus `ideas.user_id uuid NOT NULL REFERENCES users(id)`. The follow-up "add an idea to build trust mcp directory rateme12345" then failed four different ways across four asks — `SELECT id FROM users LIMIT 1` (idea silently attached to demo user Alice), an invented all-zero UUID (23503), and `WHERE email='rateme12345'` (0 rows, silent no-op) — because no honest SQL exists for that request against that schema. Normalizing an owner table is a reasonable read of the goal; making the owner *required* on a guess is not. Nullable costs the schema nothing a chat-created DB depends on (no ORM, no app code asserting the invariant) and buys the whole write path a legal answer, which is what lets the ask pipeline clarify a genuine ambiguity instead of inventing one. PK members are excluded because a link table keyed on its parents (`idea_tags(idea_id, tag_id)`) genuinely cannot exist without them, and a nullable PK column is not legal Postgres. Bonus: `ON DELETE SET NULL` on a `NOT NULL` column is a provision-time DDL error the free chain does emit; this removes that failure mode.
- **Consequence in code:** `relaxSpeculativeForeignKeys` is exported from `apps/api/src/db-create/infer-schema.ts` and applied to the Zod-validated plan before it is returned, so the compiled DDL, the plan echoed to the client, and `schema_text` all agree. Fewer sample rows are pruned as `not_null_violation` ([`SK-HDC-019`](./SK-HDC-019-deterministic-sample-row-salvage.md)) — the FK check there only fires on non-null values, so seeding strictly improves. `infer-schema.test.ts` pins the production ideas shape: owner FK relaxed, `title`/`id` and the `idea_tags` composite key untouched, `foreign_keys` unchanged, no input mutation, identity return on an FK-free plan.
- **Alternatives rejected:**
  - **Bias the schema-inference prompt against normalizing an owner table for single-actor goals.** Probabilistic, untestable, and it destroys a legitimately useful table; the dead-end is the `NOT NULL`, not the table. Same reasoning that made [`SK-HDC-019`](./SK-HDC-019-deterministic-sample-row-salvage.md) the deterministic complement to [`SK-LLM-033`](../../llm-router/decisions/SK-LLM-033-schema-infer-insertable-sample-rows.md).
  - **Give the FK column a `DEFAULT` pointing at a seeded demo row.** Bakes silent misattribution into the schema — exactly the production failure, just deterministic.
  - **Skip demo seeding instead.** Seed rows are the stranger's first value ([`GLOBAL-020`](../../../decisions/GLOBAL-020-zero-config-first-60s.md)); they are not what dead-ends the write, the constraint is.
  - **Tell the planner which demo rows exist (a seed-evidence note in the planning prompt).** Would put real cell-values on the planning lane, which [`GLOBAL-037`](../../../decisions/GLOBAL-037-schema-only-llm-egress.md) reserves to the founder — left as an open question in `FEATURE.md`, not implemented.
