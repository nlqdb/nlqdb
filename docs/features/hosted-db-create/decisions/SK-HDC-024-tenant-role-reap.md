# SK-HDC-024 — Tenant roles are reaped once no `databases` row needs them; dropping is founder-gated

- **Decision:** The hourly `tenant_role_reap` job (`apps/api/src/db-sweep/role-reap.ts`, one `JOBS` row per SK-HDC-023) treats a `tenant_<hash>` role as live while any D1 `databases` row names its tenant. Every other `tenant_*` role is an orphan: its grants are revoked schema by schema, then the job runs `DROP ROLE`. Each run drops at most 50 roles, and each role is dropped in its own Neon transaction. The job always logs `{rolesTotal, rolesLive, reaped, failed}`. It drops roles only while `TENANT_ROLE_REAP=1` is set on the api Worker; with the flag unset it only counts.
- **Core value:** Bullet-proof, Simple, Free
- **Why:** Neon caps a branch at **500 roles**, and the provisioner mints one role per tenant (`tenant-role.ts`). Nothing dropped them. Every deleted DB (SK-HDC-016), swept anon DB (SK-ANON-002) and adopted anon tenant (SK-ANON-003) leaked a role. On 2026-10-14 production hit 500/500: hosted create returned Neon 422 `roles limit exceeded`, and every `ci-smoke-*` branch inherited the full set, so the `apps/api smoke` check failed. D1 is the truth for "this tenant has a DB" (it is what `resolveDb` reads), so a role absent from D1 can never be reached. If a live role is reaped anyway (a create racing the read), the exec path recreates it on the next query (SK-ASK-024).
- **Consequence in code:** There is one reaping mechanism. DB delete and the anon sweep stay D1-only, and the next hourly tick frees the role. The job uses explicit `REVOKE`s instead of `DROP OWNED BY`, because on PG18 `DROP OWNED BY` also removes the owner's ADMIN membership, which `DROP ROLE` needs. A role holding a privilege outside its own schemas fails with 2BP01; the job logs `tenant_role_reap_failed` and skips it. It never forces the drop. If D1 returns zero tenants, the job drops nothing.
- **Alternatives rejected:** *Drop the role inside `DELETE /v1/databases/:id`*: that is a second mechanism, and it misses swept and adopted tenants. · *One shared role for every tenant*: it gives up per-tenant schema isolation, and RLS alone does not stop the shared owner from reaching another tenant. · *A paid Neon plan for more roles*: it costs money and the leak would still grow (`cost-ladder.md`). · *Ungated drops*: dropping production roles is an owner decision. The flag puts the first drop in the founder's hands, and the count tells them what that drop will remove.
