# SK-SCHEMA-012 — `insert(table, rows)` lands rows with no model: types from the values, unseen shape widened in the same transaction

- **Decision:** `POST /v1/insert` (`@nlqdb/sdk` `insert({ db, table, rows })`) is the app write path of `GLOBAL-041` Phase A step 10. `apps/api/src/insert/plan.ts` maps each JSON key to a lower_snake_case column (`serverId` → `server_id`, `$schema` → `schema`; a key with no letter, or two keys on one column, is `invalid_body`). It reads the DB's real columns from `information_schema`, then emits a `WidenPlan` and one parameterised `INSERT … RETURNING *`. An unseen table gets `CREATE TABLE`, an unseen key gets `ADD COLUMN … NULL`. Both go through `compile-write-ddl.ts`, the `sql-validate-ddl.ts` allow-list and `buildWidenBatch`, so widen and rows commit or roll back together (`SK-SCHEMA-008`), and `schema_hash` is CAS-rewritten (`SK-SCHEMA-011`). **Types are the widest that never block a later write**: number → `numeric`, string → `text`, object/array → `jsonb`, boolean → `boolean`; mixed values → `text` (`jsonb` if any is an object). The only narrower guess is a new table's `id`: all-integer → `bigint` identity, all-uuid → `uuid`; with no `id` key the table gets a generated `id uuid`. A sharper type or name is a later proposal (step 11, `SK-SCHEMA-009`). **`SK-TRUST-001` scope:** the insert commits without a preview hop. The caller wrote the exact values, so there is no intent-to-effect gap to negotiate, the same footing as `/v1/run` (`GLOBAL-015`). The widen is additive only, and the response carries `widen.ddl` plus the stored rows as the record of what changed. Account keys only: `pk_live` and anon are read-only (`forbidden`). Hosted Postgres only (`invalid_request` otherwise). At most 1 000 rows / 30 000 values per call. A key a row omits is `DEFAULT` (a generated `id`, `created_at DEFAULT now()`), an explicit `null` is NULL (a null `id` is `DEFAULT` too, the key being NOT NULL). An explicit integer `id` first lifts the `id` sequence past it, in the same transaction, so a generated id never collides with an app-supplied one; a system column name (`xmin`, `ctid`, …) is `invalid_body`. A `42P07`/`42701` from a concurrent widen re-observes and re-plans once. An `Idempotency-Key` replays the committed response for 24 h (KV `insert` scope, `GLOBAL-005`), so an SDK retry never lands the rows twice.
- **Core value:** Goal-first, Bullet-proof, Simple, Free
- **Why:** Every `GLOBAL-041` KPI-1 miss traced to the free-LLM plan stage on long writes. A JSON value already names its type, so a model adds latency, quota burn and failure modes and no information. Widest-safe types keep END_GOAL row 3's promise: a better type arrives later as a proposal, never as a blocked write. Snake-casing makes the inferred schema read like a hand-made Postgres one.
- **Consequence in code:** `apps/api/src/insert/{plan,orchestrate}.ts`; the orchestrator takes no LLM dependency, so 0 `llm.*` spans under an insert holds by construction (unit-pinned). The KPI-1 sample is `databases.inserts_infer_{ok,failed}` (migration `0037`): bumped once per insert that named an unseen table or field, stranger-walker-excluded. `computeGtmMetrics.engine.insertInferenceRate` reads it; `asks_extend_*` (`SK-SCHEMA-010`) stays the chat path's number. The insert runs as the shared Neon owner (DDL needs it; the schema is the DB's own), as `extendWrite` does.
- **Alternatives rejected:** *Route `insert()` through `/v1/ask` extend.* That is the LLM write path this step removes. · *Tight types (`integer`, `timestamptz`, `uuid`) from the first value.* The next `1.5` or `"n/a"` blocks a write; the guess belongs to the async proposal. · *Preserve camelCase as quoted mixed-case identifiers.* Every reader then has to quote, and the inferred schema stops looking hand-made. · *Preview-then-confirm on every app insert.* That is a round-trip per write for a caller who has nothing to negotiate.
