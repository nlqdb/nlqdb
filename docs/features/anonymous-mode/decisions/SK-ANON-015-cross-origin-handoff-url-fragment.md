# SK-ANON-015 — Cross-origin prompt/identity handoff rides the URL fragment; every marketing→app navigation carries it

- **Decision:** `nlqdb.com` and `app.nlqdb.com` (`SK-AUTH-016`) are different browser origins, so the `SK-ANON-011` slots and the `SK-ANON-001` token don't cross on their own. **Every marketing→app navigation that has prompt state to carry** puts `{anon, pending, draft}` in the URL **fragment** (`#nlq=<url-encoded json>`) — not just the sign-in arc: the `auth_required` redirect, *and* every content CTA that seeds a goal before sending the visitor to `/app/*` (`/solve/<slug>`, `/vs/<slug>`, `/agents`). Links into the app stay **relative** (no direct `app.nlqdb.com` hrefs) so the 301 to the app host keeps the fragment. The receiving page imports the payload into localStorage and strips the fragment **before** anything reads `nlqdb_anon` — otherwise a freshly minted app-origin token wins the race and orphans the DB the visitor already started; a differing pre-existing token is parked in `nlqdb_anon_prev` and adopted alongside the active one. **The fragment is attacker-writable**, so the import is double-gated — shape validation (string fields, length caps, the `anon_` mint format) AND a trusted referrer (same origin, `*.nlqdb.com`, or localhost; `Base.astro` pins `strict-origin-when-cross-origin`, and a referrer can't be forged upward). A foreign or missing referrer drops the payload but still strips the fragment, blocking anon-token fixation (login-CSRF) and prompt clobbering via a crafted link. The `replay=1` exception to the `?db=` pin is `SK-ANON-014`'s.
- **Core value:** Bullet-proof, Effortless UX, Seamless auth
- **Why:** Fragments are never sent in HTTP requests (RFC 3986 §3.5) and are excluded from `Referer`, so prompts and bearers stay out of server logs and analytics — the transport properties `SK-ANON-011`/`SK-ANON-012` demand. Scope is "every navigation" because the narrower "sign-in arc only" reading shipped a silent funnel break: the `/solve`, `/vs` and `/agents` CTAs called `saveDraft` on the marketing origin and then navigated to `/app/new/`, so all 69 content pages discarded the visitor's goal and landed them on an empty input — each file correct in isolation, wrong across the origin split. `SK-ANON-011`'s "never lose a prompt" is a property of the arc, not of one page.
- **Consequence in code:** `apps/web/src/lib/handoff.ts` (`attachHandoff` / `importHandoffFromLocation`); the fragment import at the top of `sign-in.astro` and of `app/new.astro` (ahead of `getOrMintAnonToken`); `attachHandoff` on the `/solve`, `/vs`, `/agents` CTAs. `lib/posthog.ts` strips the fragment from `$current_url`/`$referrer` so the bearer can never reach the analytics store even if capture beats the strip. Guarded by `client-nav-integrity.test.ts` — a file that holds prompt state (`saveDraft`/`makeDraftSaver`/`savePending`/`importHandoffFromLocation`) and then navigates without `attachHandoff` fails CI by name — plus the two-origin round-trip cases in `handoff.test.ts`. A runtime-computed `<a href={expr}>`, or a save/link split across two files, still gets past the sweep; the walkers are the backstop. The stranger walkers assert the *outcome* (the goal is in the create input), never `localStorage` on the sending origin: that read raced the navigation and silently passed pre-merge.
- **Alternatives rejected:**
  - Query-string transport — leaks prompt + bearer to server logs; rejected in `SK-ANON-011` and still banned.
  - Cookie stashed by a cross-site fetch from the marketing origin — third-party cookie partitioning (Chrome, Safari ITP) silently drops it; that is the failure mode the post-signin fallback already exists for.
  - Server-side prompt store keyed by anon hash — Phase 2+ per `SK-ANON-011`.
