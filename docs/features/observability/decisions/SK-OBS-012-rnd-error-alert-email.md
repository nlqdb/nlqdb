# SK-OBS-012 — Unexpected server/client errors also fire a throttled, redacted R&D alert email

- **Decision:** On an **unexpected** error — the central `app.onError` 500 (server) or a `/v1/errors/web` client crash — the API sends a best-effort diagnostic email to **`rnd@nlqdb.com`** via the shared `notify()` rail + the `internalErrorAlertEmail` template (`alertRnd()` in `apps/api/src/internal-alert.ts`). It is **complementary to Sentry** ([`SK-OBS-011`](../FEATURE.md)), not a replacement: Sentry stays the canonical grouping/alerting UI; the email is a low-friction founder-inbox heads-up. Only *unexpected* errors trigger it — expected 4xx (auth, rate-limit, clarify, model_unavailable) never do.
- **Core value:** Bullet-proof, Honest latency, Simple
- **Why:** A founder inbox ping surfaces a live incident without opening a dashboard. But two constraints shape it hard:
  - **Shared Resend quota (`runbook §Resend`: free tier, 3,000/mo)** — the *same* pool magic-link sign-in draws from. So every alert passes a KV throttle: per-signature dedup (one alert per unique error per hour) + a hard `DAILY_CAP` (20/day) backstop, so an error storm can never drain the quota and break sign-in email. OTel + Sentry + `wrangler tail` remain the complete record; the email is only the heads-up.
  - **PII invariant ([`SK-OBS-008`](../FEATURE.md) / `SK-WEB-001`)** — messages/stacks/URLs carry emails, tokens, API keys. Every field is redacted through `redactPii` (`@nlqdb/otel`) before it reaches the template, exactly as the `/v1/errors/web` span attributes already are — the alert must not become a raw-PII side channel through Resend into an inbox.
- **Consequence in code:** `alertRnd()` (KV dedup + daily cap, best-effort, never throws) is called via `waitUntil` from `app.onError` (server, with method/path/error/stack/principal/colo/UA) and from the `/v1/errors/web` handler (client, after its existing per-isolate dedup). New alert types ride the same rail. Tuning the cap/cooldown is a constant edit, not new plumbing.
- **Alternatives rejected:**
  - Email on every error, unthrottled — drains the shared 3k/mo Resend quota and breaks sign-in during exactly the incident you most need to log in for.
  - Raw (un-redacted) context for "maximum detail" — routes Bearer tokens / API keys / user emails through a third party into an inbox, breaking the [`SK-OBS-008`](../FEATURE.md) redaction invariant. Redacted fields still carry the signature, path, and stack shape that triage needs.
  - LogSnag / Sentry-only, no email — the established channels stay; this adds the founder-inbox push the request asked for, complementary to them.
